# Moonraker metadata: teaching the host our name

Fable Slicer emits the PrusaSlicer/Orca-convention metadata comments that
print hosts parse (`; total layers count`, `; layer_height`,
`; filament_type`, the first-layer targets, …) — see `emit_host_metadata`
in `engine/src/emit.rs`.

Moonraker will not read them until it recognizes the slicer by name.

## Why

`moonraker/components/file_manager/metadata.py` picks a parser by matching
the file's header/footer against a hardcoded list of slicer names:

```python
known_aliases = [
    "PrusaSlicer", "SuperSlicer", "OrcaSlicer", "MomentSlicer",
    "SliCR-3D", "A3dp-Slicer", "QIDISlicer"
]
pattern = r"({ids})\s(.*)\son".format(ids="|".join(known_aliases))
```

No match falls back to `UnknownSlicer`, which recovers only the object
height and first-layer height from `G1 Z` moves plus the temperatures from
`M109`/`M190`/`M191`. That is exactly what a Fable-sliced file shows today:
`"slicer": "Unknown"`, no layer count, no time estimate, no filament totals,
no thumbnails.

Our header line is shaped to match the moment the name is on the list —
`<name> <version> on <machine>`, where the "on" clause names the printer
profile rather than a timestamp, so the same job keeps emitting the same
bytes:

```
; generated by Fable Slicer 0.0.0 on sovol-zero-custom
```

## The host-side patch

One entry, on the printer. Adjust the path if Moonraker lives elsewhere
(`~/moonraker` is the standard install):

```bash
ssh <user>@<printer-host>
cd ~/moonraker
# check the list first — line numbers move between releases
grep -n "known_aliases" -A 4 moonraker/components/file_manager/metadata.py
sed -i 's/"PrusaSlicer", "SuperSlicer", "OrcaSlicer", "MomentSlicer",/"PrusaSlicer", "SuperSlicer", "OrcaSlicer", "MomentSlicer", "Fable Slicer",/' \
    moonraker/components/file_manager/metadata.py
sudo systemctl restart moonraker
```

Then re-scan an existing file (uploading again also works):

```bash
curl -X POST "http://<printer-host>:7125/server/files/metascan?filename=<file>.gcode"
curl "http://<printer-host>:7125/server/files/metadata?filename=<file>.gcode"
```

`"slicer": "Fable Slicer"` in the response means the fields are live; the
Mainsail/Fluidd file card fills in on the next page load.

**This patch does not survive a Moonraker update** — `moonraker update`
checks out the upstream tree and the edit is gone. Re-apply, or carry it
upstream (below).

## Upstream

The durable fix is the same one-line addition in
[Arksine/moonraker](https://github.com/Arksine/moonraker) — a new entry in
`known_aliases`. Nothing else is needed: every field Moonraker's PrusaSlicer
parser looks for is already emitted in the exact spelling it expects, which
is why the local patch alone is sufficient to light up the whole card.

## What is still missing after the patch

Thumbnails. Moonraker reads them as base64 PNG blocks in the header:

```
; thumbnail begin 300x300 13600
; <base64 …>
; thumbnail end
```

Generating those needs a render (the GUI has an offscreen path) and a real
PNG compressor — the minimal encoder in `gui/src/offscreen.rs` writes
uncompressed deflate, which would put ~480 KB of base64 at the top of every
file. Not done yet.
